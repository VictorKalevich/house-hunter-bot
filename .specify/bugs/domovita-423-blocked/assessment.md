# Bug Assessment: 423 Locked от domovita.by не считается защитой от ботов

- **Slug**: domovita-423-blocked
- **Created**: 2026-11-23
- **Source**: pasted text (наблюдение на живом боте при выкате T088, логи `wrangler tail` и таблица `sources` в D1)
- **Verdict**: valid
- **Severity**: medium

## Report (verbatim or summarized)

> domovita.by на все запросы бота с адресов Cloudflare (живой выкат 2026-11-23) отвечает HTTP 423 Locked — 10+ раз
> подряд по всем семи лентам, объявлений 0. Адаптер (src/jobs/poll-feeds.js blockedResponse) считает страницей
> защиты только 403, 429, заголовок cf-mitigated и маркеры в теле, поэтому 423 идёт как обычная HTTP-ошибка:
> состояние failing, повтор ленты через 5 минут, к сайту — каждую минуту, без часовой паузы (US5-2). Решение
> владельца: 423 считать страницей защиты, как 403/429 — состояние blocked, повторная проверка через час и дальше по
> backoff, обход защиты не делаем.

Уточнение по данным 2026-11-23, 11:30–11:51 UTC: отказ не сплошной. Из ~20 запросов к domovita прошли два —
HTML-страница ленты в 11:34:48 (взята версия сборки `buildId`) и JSON первой страницы Витебской области в 11:44:48
(18 объявлений). Остальные — `423 Locked`. Похоже на ограничение частоты по IP: исходящие адреса Cloudflare общие
для многих Worker'ов.

## Symptom

На 423 бот ставит domovita в `failing` и опрашивает её дальше раз в минуту, по очереди по лентам. Каждый случайный
успех сбрасывает счётчик и шлёт владельцу «снова работает», а через три 423 подряд уходит новое «не отвечает». За
десять минут владелец получил три сообщения: сбой, «снова работает» в 11:44:48 и снова сбой в 11:47:48. Ожидалось
другое (US5-2, FR-005): на отказ защиты — `blocked`, одно сообщение, следующая проверка через час, дальше реже.

## Reproduction

1. Сайт отвечает на запрос страницы ленты `423 Locked` (тело любое, без маркеров капчи).
2. Тик: `doFeed` → `res.status !== 200` → `blockedResponse(res)` = false → `fail('http', '423 Locked')`.
3. Источник `failing`, лента откладывается на 5 мин, следующий тик берёт другую ленту того же сайта — запрос к
   сайту каждую минуту; после 3 подряд — сообщение владельцу «не отвечает … (3 проверки подряд)».
4. Один ответ 200 → `onSuccess` → «снова работает»; следующие 423 → снова пп. 2–3.

## Suspected Code Paths

- `src/jobs/poll-feeds.js:144` `blockedResponse()` — признаки защиты: 403, 429, `cf-mitigated`, `BLOCK_MARKERS`;
  423 среди них нет.
- `src/jobs/poll-feeds.js:314-316` `doFeed()` — не-200: `blocked`, если `blockedResponse`, иначе `http`.
- `src/jobs/poll-feeds.js:270` `doDetail()` — та же проверка для карточек (у domovita карточек нет, но правило
  общее).
- `specs/001-house-listing-alerts/contracts/source-adapter.md:92` — таблица классификации: «403, 429, капча,
  страница проверки браузера → `blocked`».

## Root Cause Hypothesis

Классификация ответа знает только коды 403 и 429 как отказ защиты. 423 Locked — нестандартный для HTTP-сайтов
код (WebDAV), его отдают некоторые системы защиты от ботов и ограничения частоты; при разработке он не встречался
(сохранённые страницы снимались не с адресов Cloudflare). Поэтому отказ защиты принят за временный сбой сервера, и
правило «реже проверять» (FR-005) не срабатывает. Уверенность: high — код и логи тиков совпадают
(`"result":"http","error":"423 Locked"`).

## Proposed Remediation

**Preferred**: в `blockedResponse()` считать 423 отказом защиты наравне с 403 и 429. Тогда `doFeed`/`doDetail` дают
`blocked`: сообщение владельцу сразу, без повтора в этом круге, проверки через 1, 2, 4, 8, 24 ч
(`BLOCKED_BACKOFF_HOURS`), обхода нет. Текст сбоя — «423, страница защиты от ботов». В контракте адаптера дополнить
строку таблицы кодом 423.

**Alternatives**:
- Учитывать `Retry-After` у 423/429 и ставить паузу по нему — точнее, но заголовки ответа domovita не известны, а
  правило FR-005 и так выполняется часовым backoff.
- Не объявлять «снова работает» после одного успеха у `blocked`-источника (гистерезис) — убрало бы мигание и при
  частичном пропуске, но это изменение поведения US5-1 сверх решения владельца; см. Open Questions.

**Files likely to change**:
- `src/jobs/poll-feeds.js`
- `specs/001-house-listing-alerts/contracts/source-adapter.md`
- `tests/e2e/source-health.e2e.mjs` (или `tests/e2e/notify.e2e.mjs`)

**Tests to add or update**:
- e2e: сайт отвечает 423 без маркеров в теле → источник `blocked` с первого ответа, одно сообщение владельцу
  «отказал боту … следующая проверка через 1 ч», следующий запрос к сайту не раньше чем через час.

## Risks & Considerations

- Частичный пропуск domovita сохраняется: если проверка через час попадёт в редкий 200, источник станет `ok` и
  владелец получит «снова работает», а следующий 423 — новое «отказал боту». Но это раз в часы, а не раз в
  несколько минут; backoff после успеха начнётся снова с 1 ч.
- Данных с domovita от этого больше не станет: с адресов Cloudflare сайт практически закрыт; обход (прокси, другие
  заголовки) запрещён FR-005 и контрактом.
- Если какой-то сайт отдаёт 423 по другой причине (не защита), он тоже уйдёт в часовую паузу — для четырёх
  сайтов проекта такого не замечено; цена ошибки — реже проверки, не потеря доступа.
- Миграций, изменений API и CPU нет.

## Open Questions

  частичный пропуск domovita будет давать пары сообщений сбой/восстановление? Решение — за владельцем, по итогам
  наблюдения после исправления; в этот bugfix не входит.
