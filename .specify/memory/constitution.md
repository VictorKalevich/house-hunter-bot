# House Hunter Bot Constitution

## Core Principles

### I. Бережно к сайтам-источникам (NON-NEGOTIABLE)

- Бот читает только публичные страницы и публичные API сайтов, без входа в аккаунт.
- Капча, блокировки и защита от ботов не обходятся. Если источник начал отказывать, бот выключает его и
  сообщает владельцу, а не меняет адреса, заголовки или прокси, чтобы прорваться.
- Каждый источник опрашивается не чаще одного раза в 15 минут, с паузами между запросами. Читаются только
  первые страницы выдачи, отсортированной по дате.
- Хранится только то, что нужно для фильтров и уведомления: ссылка, цена, площади, координаты, место,
  дата и одна ссылка на фото. Тексты и фотографии сайтов целиком не копируются.

### II. Ни одного дубля, ни одного пропуска

- Объявление уникально по паре «источник + id на сайте». Пользователь получает о нём одно уведомление,
  даже если cron сработал дважды, вызов упал на середине или объявление подняли в выдаче.
- Если уведомление не ушло, оно уходит при следующем запуске, а не теряется.
- Сбой одного источника не мешает остальным. Ошибки разбора видны владельцу и не превращаются молча в
  «новых объявлений нет».

### III. Спецификация до кода

- Любое изменение поведения начинается с обновления спецификации в `specs/` по процессу Spec Kit:
  `/speckit-specify` → (`/speckit-clarify`) → `/speckit-plan` → `/speckit-tasks` → `/speckit-implement`.
- Спецификация — источник истины. Если код и спецификация расходятся, правится то, что неверно, и
  расхождение фиксируется в той же ветке.
- Каждая фича живёт в своей ветке `NNN-короткое-имя` и своей папке `specs/NNN-короткое-имя/`.

### IV. Бесплатно и без своего сервера

- Проект работает на бесплатном тарифе Cloudflare Workers + D1 + Cron Triggers.
- Код укладывается в лимиты бесплатного тарифа: ≤ 10 мс CPU на вызов, ≤ 50 внешних запросов (включая
  запросы к D1) на вызов, ≤ 100 000 запросов в сутки. Работа, которая не помещается в один вызов,
  делится на пачки между запусками.
- Внешние сервисы (геокодирование, маршруты) — только бесплатные и только в пределах их правил
  использования. Их результаты кешируются в D1, чтобы одно и то же не запрашивалось дважды.

### V. Проверено до выката

- Разбор каждого источника покрыт тестами на сохранённых страницах сайта. Когда сайт меняет вёрстку,
  сначала добавляется новая сохранённая страница и падающий тест, потом правится разбор.
- Фильтры (цена, площадь дома, площадь участка, расстояние) и расчёт расстояний покрыты юнит-тестами,
  включая границы диапазонов и объявления, где поля не указаны.
- Перед выкатом проходит сквозной тест: локальный Worker, имитация Telegram API и сайтов, полный цикл
  «новое объявление → фильтр → одно уведомление».

### VI. Просто для пользователя

- Весь интерфейс на русском языке и работает в Telegram на iOS, Android и компьютере без установки
  чего-либо ещё.
- Критерии поиска настраиваются кнопками или формой, без команд с параметрами.
- Уведомление сразу показывает главное: цену, площадь дома и участка, расстояние, место и ссылку на
  объявление.

### VII. Только дизайн-система (NON-NEGOTIABLE)

- Любой интерфейс проекта (мини-приложение Telegram, страницы, витрины) строится только из токенов и
  компонентов `design-system/`: `tokens.css` (цвета, типографика, отступы, радиусы, размеры) и
  `components.css` (компоненты `ds-*`).
- В коде интерфейса запрещены свой CSS, атрибуты `style`, классы вне `ds-*`, «сырые» цвета и размеры в px;
  это проверяет автотест `tests/design-system.test.mjs`.
- Нужен новый элемент — сначала он добавляется в дизайн-систему (токен → компонент → `preview.html` → описание
  в `design-system/README.md`), потом используется.
- Цвета опираются на тему Telegram (`--tg-theme-*`), чтобы светлая и тёмная темы работали сами. Цвета, не
  зависящие от темы, дают тексту на них контраст не меньше 4.5 : 1.

## Безопасность и данные

- Webhook принимает запросы только с секретным заголовком `X-Telegram-Bot-Api-Secret-Token`.
- Секреты (`BOT_TOKEN`, ключи внешних сервисов) хранятся только в секретах Cloudflare и никогда не
  попадают в репозиторий; `.dev.vars` и `.env*` в `.gitignore`.
- Текст с сайтов и от пользователей экранируется в сообщениях бота и никогда не вставляется в HTML как
  разметка.
- О пользователе хранится минимум: Telegram ID, имя, критерии поиска и отметки об отправленных
  уведомлениях.

## Процесс разработки

- Платформа разработчика — Windows; скрипты Spec Kit — PowerShell (`.specify/scripts/powershell/`).
- Проект живёт в `C:\ClaudeProjects\house-hunter-bot\`; в самой `C:\ClaudeProjects\` файлы не создаются.
- Документация библиотек и API (Cloudflare Workers, D1, Wrangler, Telegram Bot API и других) берётся
  через Context7, а не по памяти.
- Сообщения коммитов — по-русски или по-английски, кратко и по сути; одна логическая единица на коммит.
- README.md обновляется в той же ветке, что и фича, если фича меняет установку, настройку, секреты,
  команды или то, как пользоваться ботом. В `tasks.md` каждой такой фичи есть отдельная задача на README.
- Перед коммитом проходят быстрые тесты (`npm test`, в том числе проверка дизайн-системы), перед слиянием и
  выкатом — сквозной тест.

## Governance

- Конституция главнее остальных договорённостей. Каждый план (`plan.md`) содержит раздел
  Constitution Check с проверкой всех принципов.
- Поправки: правка этого файла + Sync Impact Report вверху + версия по SemVer (MAJOR — снятие или
  переопределение принципа, MINOR — новый принцип или раздел, PATCH — уточнения).
- Нарушение принципа допускается только с записью в Complexity Tracking плана и обоснованием.
- Рабочие подсказки для агента — в `CLAUDE.md`.
