# Research: уведомления о новых домах с участками

**Фича**: `001-house-listing-alerts` | **Дата**: 2026-11-22 | **План**: [plan.md](plan.md)

Источники: пробные запросы к сайтам 22.11.2026 (по 9–16 запросов на сайт, честный User-Agent, паузы), официальные
правила сервисов, документация Cloudflare (Context7: `/llmstxt/developers_cloudflare_workers_llms-full_txt`,
`/llmstxt/developers_cloudflare_d1_llms-full_txt`, `/cloudflare/workers-sdk`) и Telegram Bot API (Context7:
`/websites/core_telegram_bots_api`; страницы о мини-приложениях в Context7 нет, источник — core.telegram.org/bots/webapps).
Решения владельца при планировании: соблюдать robots.txt (Конституция 1.2.0) и считать самый быстрый маршрут.

## R1. Источники объявлений

### kufar.by

- **Decision**: открытый JSON API выдачи:
  `GET https://api.kufar.by/search-api/v2/search/rendered-paginated?cat=1020&typ=sell&sort=lst.d&size=30&lang=ru`;
  следующая страница — `&cursor=<token>` из `pagination.pages[label="next"]`. Одна лента на всю страну, круг раз в
  15 мин, до 3 страниц.
- **Поля** (`ads[]`): `ad_id` — номер (растёт по всему Куфару); `ad_link`; `price_usd`/`price_byn` — строки в
  центах, делить на 100, `"0"` — нет цены; `ad_parameters[p]`: `house_type_for_sell` (берём Дом, Дача, Коттедж,
  Часть дома, Таунхаус; «Прочее» отбрасываем), `size` — дом, м², `size_area` — участок, сотки, `coordinates` —
  `[lon, lat]`, `region`/`area` — область и район; `account_parameters[p="address"]` — адрес словами; `list_time` —
  размещение или поднятие; фото — `https://rms.kufar.by/v1/gallery/{images[0].path}`. Имя продавца
  (`account_parameters[p="name"]`) не читаем.
- **Новое или поднятое**: даты создания нет, ~80 % ленты — поднятые. Новое = номер выше суточной отметки
  (`idKind: numeric`, data-model `sources.new_id_floor`).
- **Rationale**: всё нужное есть в выдаче; у `api.kufar.by` нет robots.txt (404); 30 объявлений — 222 КБ JSON,
  разбор ~1,1 мс; при ~44 записях в час (воскресенье) 30 объявлений покрывают ~37 мин, раз в 15 мин хватает
  первой страницы, курсор — на всплески.
- **Alternatives**: HTML `re.kufar.by/l/belarus/kupit/dom` — 1,8 МБ, а выдача с параметрами закрыта robots.txt.
- **Риски**: API без документации, может измениться — ловится классификацией `parse` и тестами на сохранённых
  ответах.

### realt.by

- **Decision**: HTML-страницы выдачи, данные — JSON в `<script id="__NEXT_DATA__">`, путь
  `props.pageProps.objects[]`. 12 лент: 6 регионов × «дома» и «дачи» — `/{brest|vitebsk|gomel|grodno|mogilev}-region/
  sale/{cottages|dachi}/` и Минская область `/sale/{cottages|dachi}/`; до 2 страниц (`?page=2`), круг раз в 20 мин.
- **Поля**: `code` — номер; ссылка `https://realt.by/sale-{cottages|dachi}/object/{code}/`; `priceRates["840"]` — $,
  `["933"]` — BYN (целые единицы); `areaTotal` — дом, м²; `areaLand` — участок, сотки; `location` — `[lon, lat]`;
  место — `townType townName`, `stateDistrictName` + «район», `stateRegionName`; `createdAt` — создание
  (`idKind: created_at`); `images[0]` — фото; платные — `paymentStatus > 0`. `contactPhones`, `contactName`,
  `contactEmail` не читаем.
- **Rationale**: robots.txt закрывает `*=` (кроме `?page=2…10`), GraphQL (`/bff/graphql`) и `/_next/data` —
  сортировка по дате недоступна. По умолчанию сначала платные, затем бесплатные по времени поднятия; на страницах
  регионов платный блок помещается на первую страницу, 12–15 бесплатных мест покрывают 15–40 мин поднятий —
  отсюда вторая страница, когда круг не догнал прошлый (правило `feeds.prev_ids`).
- **CPU**: страница региона ~900 КБ HTML, JSON ~390 КБ — `cost 2`; Минская область — 2 МБ HTML и 1,2 МБ JSON,
  разбор ~3 мс — `cost 5`, такой странице тик отдаётся целиком. JSON ищется `indexOf` по маркеру, без HTML-парсера.
- **Alternatives**: параметр сортировки (нарушает robots.txt — отклонено владельцем); страница всей страны
  `/belarus/sale/cottages/` (первые ~7 страниц — только платные).
- **Риски**: при массовых поднятиях объявление может уйти дальше 2-й страницы между кругами (принято в
  спецификации); страницы тяжёлые.

### domovita.by

- **Decision**: JSON страниц Next.js `GET https://domovita.by/_next/data/{buildId}/{регион}/houses/sale.json`
  (`?page=N` для следующих), данные `pageProps.listingCardsFromSSR.items[]`. 7 лент: `minsk`, `minskaya-oblast`,
  `brestskaya-oblast`, `vitebskaya-oblast`, `gomelskaya-oblast`, `grodnenskaya-oblast`, `mogilevskaya-oblast`; до 2
  страниц (Минская область — 3), круг раз в 20 мин. `buildId` берётся из HTML страницы раздела (встречается в
  первых ~100 КБ — чтение потока прекращается, как только он найден) и хранится в состоянии источника; 404 на
  маршруте — `buildId` устарел, в следующем тике обновить. Запасной путь — `__NEXT_DATA__` из HTML.
- **Поля**: `id`; `url`; `price.USD`, `price.BYN`; `area.total` — дом; `area_ground` — участок (по значениям —
  сотки, сверить по карточке при сборе сохранённых страниц); `address.coords.position_x` — широта, `position_y` —
  долгота; `address.town.type` + `.name`, `address.town.stateRegion.name`; район — из `title` («…, Дзержинский р-н,
  …»); `date_reception` — публикация (`idKind: created_at`); `photos[0].url`; платные — `is_vip = 3`; проверка
  раздела — `type === "OCottagesSale"` и `pageSettingsByPath.urlParams.object === "houses"`. `contacts` не читаем.
- **Rationale**: robots.txt разрешает `*?page`, запрещает прочие параметры; `/_next/` не закрыт. Сортировка по
  умолчанию — «по актуальности» (`-date_revision`): VIP, затем от новых к старым — то, что нужно. 18 карточек =
  167 КБ JSON (~1–2 мс) против 1 МБ HTML. Общей страницы на всю страну нет (404).
- **Alternatives**: HTML с `__NEXT_DATA__` всегда (в 6 раз больше трафика, `__NEXT_DATA__` на ~747-м КБ);
  `api.domovita.by` (POST, не документировано, CORS только для сайта) — отклонено.
- **Проверить при сборе сохранённых страниц**: слаги четырёх областей; входят ли дачи (`/dacha/sale`) в
  `/houses/sale` — если нет, добавить ленты дач с проверкой раздела; нужен ли заголовок `x-nextjs-data`.

### moyareklama.by

- **Decision**: HTML первой страницы раздела «Продажа домов и дач» и его подразделов — 6 лент: `/Гомель/дома_продажа/`,
  4 района города (`/Советский_район_Гомеля/дома_продажа/` и т. д.) и `/Гомельский_район/дома_продажа/`. Только первая
  страница (пагинация `/*/все/` закрыта), круг раз в 15 мин. Координаты — из карточки `/single/ad/{id}`
  (`input.ads_geo_lat`, `input.ads_geo_lng`), по одной карточке за тик для новых объявлений; если карточку
  прочитать не удалось — место по справочнику пунктов.
- **Поля** (разбор строк по известной разметке, без HTML-парсера): контейнер `div.one_advert_list[idAds]` — номер;
  ссылка `/single/ad/{id}`; платные — класс `premium`; заголовок «Дом 235 м² на участке 10 сот.» — тип, дом,
  участок (десятичная запятая, `&sup2;`); `div.price` — «312 000 р.», только BYN (пусто — нет цены); `div.address` —
  «Гомельский р-н, аг. Поколюбичи, ул. Луговая» (область — Гомельская); `div.date` — дата; фото — из
  `style="background: url('…')"` первого `div.small_img`; `var listParams` — счётчик `countAds`, `order_type`.
  `idKind: numeric`.
- **Rationale**: API, JSON и RSS нет. По умолчанию ~16 платных (порядок меняется при каждом запросе), за ними ~4
  самых свежих обычных; подразделы дают свои ~4. Сортировку cookie не меняем (принцип I: заголовки и cookie для
  обхода порядка выдачи не подбираем). 206 КБ HTML — ~1 мс.
- **Alternatives**: `/search/…` и пагинация закрыты robots.txt; Telegram-канал сайта смешивает квартиры и аренду.
  `sitemap7.xml` — проверить при реализации: если в нём новые объявления с `lastmod`, это разрешённый способ
  видеть все новые; решение — задачей в tasks.md.
- **Риски**: больше ~4 новых обычных объявлений за 15 мин в одном подразделе — часть уйдёт с первой страницы
  (поток в Гомеле — единицы в час; принято в спецификации). При исследовании агент один раз скачал 3 файла из
  закрытого `/search/js/` — бот туда не ходит, адреса лент сверяются с robots.txt.

### Общее для всех источников

- **«Новое на сайте»** (спецификация, Assumptions): бот объявление раньше не видел и оно создано ≤ 48 ч назад
  (`site_created_at`, realt и domovita) или его номер выше отметки суточной давности (kufar, moyareklama). Только
  такие объявления идут в уведомления; остальные — в список. Это убирает поток поднятых старых объявлений (~80 % у
  kufar) и экономит маршруты.
- **robots.txt**: раз в сутки скачивается и сверяется с адресами лент (свой разбор правил `Allow`/`Disallow` с `*` и
  `$`, ~50 строк, юнит-тесты). Закрыли адрес — источник `disallowed`, сообщение владельцу.
- **Типы объектов**: дом, дача, коттедж, часть дома (в том числе полдома, дуплекс, таунхаус — блокированная застройка
  с участком). Квартиры, участки без дома, «Прочее» отбрасываются.
- **Нагрузка на сайты**: не больше одного запроса к сайту в минуту; за круг: kufar 1–3, realt 12–14, domovita 7–15,
  moyareklama 6 + единицы карточек.

## R2. Платформа и расписание: Cloudflare Workers Free

- **Decision**: один Worker с двумя Cron Triggers: `* * * * *` — «тик» раз в минуту, `30 0 * * *` — суточные задачи
  (курс, чистка, суточная смена отметок номеров, сверка robots.txt). Работа делится на маленькие шаги внутри тика с
  бюджетом; состояние — в D1; аренда `locks` не даёт двум тикам работать одновременно.
- **Лимиты** (Context7, workers/platform/limits, d1/platform/limits): CPU 10 мс на HTTP-запрос и на Cron Trigger
  (ожидание `fetch` и D1 не считается); 50 подзапросов на вызов, запросы к D1 входят в них, `db.batch()` — один
  запрос; 100 000 запросов в сутки; 5 Cron Triggers на аккаунт; D1: 5 млн строк чтения и 100 тыс. записи в сутки,
  500 МБ на базу, 100 параметров в запросе. Индекс добавляет запись на каждую запись строки.
- **Бюджет тика**: CPU-оценка ≤ 6 единиц (`cost` лент из `npm run bench`, ~1 мс на единицу; внутри Worker CPU не
  измерить — `Date.now()` стоит на месте без ввода-вывода), подзапросов ≤ 45, к одному сайту ≤ 1 запроса.
  Порядок шагов: отправка уведомлений (≤ 20) → ленты (по просроченности) → нормализация и запись → отбор (≤ 50
  объявлений) → маршруты (≤ 10 пар).
- **Ёмкость**: ~2 500 страниц в сутки ≈ 4 100 единиц CPU из 8 640 (1 440 тиков × 6); к realt ~830 тиков из 1 440.
  Запросов к Worker — ~1 440 тиков + сутки + webhook и мини-приложение (< 5 000) — ≪ 100 000.
- **SC-001 (≤ 30 мин)**: круг ленты 15–25 мин + отбор и маршрут 1–3 тика + отправка в следующем тике.
- **Alternatives**: Queues (на Free 10 000 операций в сутки, 3 операции на сообщение — тесно, и лишняя сущность);
  Durable Objects с alarm (сложнее, выгоды нет); самовызов Worker'а ради дополнительного CPU (обход лимита по духу —
  отклонено); платный тариф (принцип IV).

## R3. Маршруты: «по дороге от центра» и «от выезда»

- **Decision**: основной сервис — openrouteservice, бесплатный ключ, адрес `https://api.heigit.org/openrouteservice/v2`
  (старый `api.openrouteservice.org` отключён в ноябре 2026). Пара «пункт поиска → место объявления» —
  `POST /directions/driving-car/json` с `preference: "fastest"`, `instructions: false`: длина
  `routes[0].summary.distance` и геометрия (encoded polyline, точность 5). Для пакетного «по дороге от центра»
  (заполнение списка нового поиска) — `POST /matrix/driving-car`, `metrics: ["distance"]`, 1 источник × до 3 499
  целей. Запасной — FOSSGIS OSRM `https://routing.openstreetmap.de/routed-car/route/v1/driving/{lon,lat;lon,lat}
  ?overview=full&geometries=polyline` (та же точность polyline): когда ORS не нашёл дорогу рядом с точкой (радиус
  350 м) или недоступен; не больше 1 запроса в секунду и 300 в сутки.
- **«От выезда»** (US3): маршрут декодируется, по каждому отрезку определяется, лежит ли он за границей пункта
  (отсев по bbox, затем луч); `road_exit = summary.distance × (длина отрезков за границей / геодезическая длина
  маршрута)`. Сумма всех внешних отрезков — дословно по спецификации («часть маршрута за границей»); место внутри
  границы — 0 км (US3, сценарий 3).
- **Сколько маршрутов нужно**: пара ставится в очередь, только если объявление проходит остальные условия поиска и
  нижняя оценка по прямой ≤ лимита (дорога не короче прямой; для «от выезда» — прямая минус `radius_km`). Для
  уведомлений — только новые объявления (сотни в сутки). Кеш `distances` по `(settlement_id, geo_key)` — одна пара
  считается один раз.
- **Лимиты ORS Standard**: directions 2 000/сутки, 40/мин; matrix 500/сутки, 40/мин, до 3 500 ячеек. Квота — по
  ключу (а не по IP: исходящие запросы Workers идут с общих адресов Cloudflare). 403 — суточная квота исчерпана:
  маршруты ждут сброса, список показывает расстояние по прямой с пометкой «считается».
- **Rationale**: ORS бесплатен для всех, не запрещает ботов и хранение результатов, даёт геометрию и выбор
  «fastest»; FOSSGIS — резерв без гарантий. Ответ 3–30 КБ, polyline на 0,5–5 тыс. точек — доли миллисекунды.
- **Alternatives**: `router.project-osrm.org` (только «reasonable, non-commercial», демо); Valhalla FOSSGIS (polyline
  точности 6, второй резерв при необходимости); GraphHopper Free (только «в фазе разработки», кеш только временный).
- **Атрибуция**: «© openrouteservice by HeiGIT | Data from OpenStreetMap», для FOSSGIS — ссылка
  openstreetmap.org/fixthemap.

## R4. Справочник населённых пунктов и границы

- **Decision**: локальный скрипт разработчика `scripts/build-settlements.mjs` (Node, без новых инструментов) через
  Overpass API собирает: все `node[place~"^(city|town|village|hamlet|isolated_dwelling)$"]` Беларуси (~22 750 пунктов:
  `name:ru`, `name:prefix:ru`, `addr:district`, `addr:region`); русские названия районов и областей — по `name:ru`
  границ `admin_level` 6 и 4; полигоны границ — только у городов, посёлков и агрогородков (relation с `place=city|town`
  и `place=village` + `name:prefix:ru=агрогородок`, порядка 2 тыс.), упрощение Дугласа–Пекера с допуском 30 м.
  Остальным — окружность: хутор 0,15 км, деревня 0,4 км, прочее 0,5 км. Результат — `seeds/settlements.sql`
  (~4 МБ), в репозитории; загрузка — `wrangler d1 execute --file`.
- **Rationale**: деревни меньше километра — разница «от центра» и «от выезда» в сотнях метров, а полигоны 22 тыс.
  деревень — массовая выгрузка, против правил публичного Overpass. Сборка разовая; `--overpass-url` позволяет взять
  другой экземпляр Overpass, если основной перегружен (22.11 отвечал 502).
- **Alternatives**: выгрузка Geofabrik `belarus-latest.osm.pbf` (336 МБ) + osmium — точнее для деревень (~99 %
  покрыты полигонами `admin_level=10`), но требует osmium на Windows; оставлена как путь улучшения. Nominatim как
  справочник — запрещено правилами (автодополнение, перебор).
- **Подсказки** (FR-007): индекс по `name_norm`, диапазон по началу строки, ≤ 10 строк, в ответе район и область.
- **Лицензия ODbL**: в README, `/start` (строка внизу) и подвале мини-приложения — «Данные © участники
  OpenStreetMap (ODbL)»; скрипт сборки — в репозитории (share-alike производной базы).

## R5. Место объявления без координат

- **Decision**: свой справочник, без внешних запросов: нормализация (нижний регистр, ё → е, снять «д.», «аг.», «г.п.»,
  «п.», «х.», «г.»; «р-н» → «район»), поиск по названию + району + области. Неоднозначно или не найдено — место не
  определено: при заданном расстоянии объявление не подходит (крайний случай спецификации). Координата — центр
  пункта, `geo_approx = 1` («≈»).
- **Rationale**: у kufar, realt и domovita координаты есть почти всегда; у moyareklama — в карточке. Справочник
  нужен как запасной путь.
- **Alternatives**: Nominatim — периодические запросы из приложения его правила называют массовым геокодированием
  (≤ 4 в минуту, «strongly discouraged»), плюс общие IP Cloudflare — не используем.

## R6. Курс USD/BYN

- **Decision**: раз в сутки `GET https://api.nbrb.by/exrates/rates/USD?parammode=2&ondate=YYYY-MM-DD` →
  `Cur_OfficialRate / Cur_Scale`, в таблицу `rates`. Нужен для объявлений только в BYN (moyareklama); kufar, realt и
  domovita дают цену в $ сами.
- **Rationale**: официальный курс, как в спецификации; на выходные API отдаёт курс пятницы; нет курса на сегодня —
  берётся последний известный.

## R7. Telegram

- **Webhook**: `setWebhook` с `secret_token`; Worker сверяет `X-Telegram-Bot-Api-Secret-Token` (раздел «Безопасность»);
  `allowed_updates: ["message", "callback_query"]`.
- **Интерфейс**: мини-приложение для поисков и списка (FR-011: форма; дизайн-система уже рассчитана на него:
  `ds-suggest`, `ds-options`, `ds-listing`, `ds-pager`); чат — главное меню, уведомления, действия владельца.
  Кнопки `web_app` и кнопка меню `setChatMenuButton` открывают мини-приложение без настройки в BotFather.
- **Проверка мини-приложения**: заголовок `Authorization: tma <initData>`; подпись HMAC-SHA256 с ключом
  `HMAC_SHA256("WebAppData", BOT_TOKEN)` по строке «пары `key=value` без `hash`, по алфавиту, через `\n`»; свежесть
  `auth_date` ≤ 24 ч; Web Crypto (`crypto.subtle`) есть и в Workers, и в Node 24 — один модуль, юнит-тесты.
  Источник правила — core.telegram.org/bots/webapps («Validating data received via the Mini App»).
- **Уведомления**: `sendMessage`, `parse_mode: HTML` с экранированием, превью — фото через `link_preview_options`
  (не `sendPhoto`: нет отказа, если сайт не отдал картинку Telegram'у), кнопка-ссылка «Открыть объявление».
  429 → `parameters.retry_after`; 403 → пользователь заблокировал бота. Не больше 20 сообщений за тик и 1 в секунду
  в чат.
- **Приглашения**: deep link `https://t.me/<бот>?start=inv_<token>` — параметр до 64 символов `A-Za-z0-9_-`.

## R8. Мини-приложение и дизайн-система

- **Decision**: `src/app/index.html` + `src/app/app.js` — без сборщика и фреймворка. Worker импортирует их и
  `design-system/tokens.css`, `components.css` как текстовые модули (Wrangler по умолчанию импортирует `.html` как
  строку; для `.css` и `src/app/*.js` — правило `rules: [{ type: "Text", globs: [...] }]`) и подставляет CSS на место
  `/*@design-system*/`. Скрипт Telegram `telegram-web-app.js` выставляет `--tg-theme-*`, на них опираются токены.
- Текст с сайтов выводится только через `textContent` (раздел «Безопасность»). Классы — только `ds-*`;
  `tests/design-system.test.mjs` проверяет `src/app/` (принцип VII). Если элемента не хватит — сначала в дизайн-систему.
- **Alternatives**: Workers Static Assets (тогда CSS пришлось бы вставлять сборкой); React/Vite (сборщик, тяжелее для
  10 мс и для правила «только ds-*»).

## R9. Ни одного дубля, ни одного пропуска

- Объявление — `UNIQUE (source, external_id)`; уведомление — `UNIQUE (user_id, source, external_id)` +
  `INSERT OR IGNORE` в одном `db.batch()` с переводом объявления в `done` (batch — транзакция): повтор тика или
  падение на середине не дают второго уведомления.
- Отправка: `pending → sending` (захват строки) → `sendMessage` → `sent` сразу следующим запросом. Ошибка с ответом —
  повтор (FR-015). Строка, зависшая в `sending` > 10 мин (вызов прервали после отправки, до записи), → `uncertain`
  без повтора: SC-002 важнее, а такой обрыв — редкость (CPU отправки — доли миллисекунды).
- Тик держит аренду `locks` 5 мин; второй тик в это время выходит сразу.

## R10. Тесты и проверка CPU

- **Decision**: `node:test` (как уже в проекте). `npm test` — быстрые: дизайн-система, адаптеры на сохранённых
  страницах `tests/fixtures/<source>/`, фильтры, расстояния (гаверсинус, polyline, «от выезда», окружность),
  нормализация, robots.txt, подпись мини-приложения, тексты сообщений. `npm run test:e2e` — сквозной: Miniflare
  (`new Miniflare({ scriptPath, modules, d1Databases, outboundService })`) поднимает Worker с локальной D1,
  `outboundService` подменяет сайты, Telegram, ORS и НБ РБ; сценарии «новое объявление → фильтр → одно
  уведомление», повтор тика, сбой источника, приглашение (принцип V). `npm run bench` — время разбора каждой
  сохранённой страницы против `cost`.
- **Alternatives**: `@cloudflare/vitest-pool-workers` — официальный путь, но второй раннер тестов; Miniflare из
  `node:test` даёт то же (D1, cron, подмена `fetch`) одним раннером.

## R11. Язык и инструменты

- **Decision**: JavaScript (ES-модули) с JSDoc, без TypeScript и сборки — так же, как существующие тесты `.mjs`;
  Wrangler сам собирает Worker. Node 24 (у разработчика v24.21.0), Wrangler 4.x и Miniflare 4.x — devDependencies.
  Зависимостей времени выполнения нет: polyline, гаверсинус, robots.txt, HMAC — свои маленькие модули с тестами.
- `wrangler.jsonc`: `main: src/index.js`, `d1_databases` (`DB`), `triggers.crons`, `rules` для текстовых модулей,
  `observability.enabled: true`; `compatibility_date` — актуальная на момент реализации. Секреты: `BOT_TOKEN`,
  `WEBHOOK_SECRET`, `OWNER_TELEGRAM_ID`, `ORS_API_KEY`; переменные: `BOT_USERNAME`, `PUBLIC_URL`.

## R12. Риски

| Риск | Что делаем |
|---|---|
| Сайт меняет вёрстку или внутренний API (kufar API, `_next/data`) | Классификация `parse`, сообщение владельцу ≤ 1 ч, сохранённые страницы и падающий тест перед правкой |
| Сайт не пускает запросы с адресов Cloudflare | Проверка после выката (quickstart, шаг «Источники»); `blocked` + сообщение; обход не делаем |
| Страница realt Минской области близка к лимиту CPU | Тик целиком под неё; `npm run bench`; если не помещается — читать только первую страницу этой ленты |
| Квота ORS исчерпана (большой новый поиск в режиме «от выезда») | Список показывает «по прямой, считается»; уведомления в приоритете над заполнением списка |
| Массовые поднятия выталкивают новое за пределы читаемых страниц | Принято в спецификации; правило «круг не догнал — следующая страница» |
| Overpass перегружен при сборке справочника | Разовая сборка, повтор позже или другой экземпляр (`--overpass-url`) |
